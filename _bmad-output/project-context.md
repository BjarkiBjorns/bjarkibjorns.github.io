# Project Context for AI Agents

_Critical rules and patterns for the **lissa** project. These are unobvious details agents would otherwise miss — not general best practices._

---

## Technology Stack & Versions

- **p5.js v1.9.4** — CDN-loaded global mode
- **p5.sound v1.9.4** — loaded by `index.html` **only over http(s)**. On `file://` its AudioWorklet fails and aborts p5 before `setup()`, so it is skipped there; the mic only works on the deployed site or localhost.
- **Vanilla JavaScript (ES6+)** — no TypeScript, no bundler, no transpiler
- **HTML5 / CSS3** — single `index.html` entry point, no template engine
- **No package manager** — zero npm/yarn/bun, no `node_modules`
- **No build step for the app** — files served directly; refresh browser to see changes. The one exception is `presets/presets.js`, regenerated by `python3 presets/build-presets.py` (see Presets).
- **No test framework** — no test files exist

## File Layout

All live files are in `code/` (the project root):

- `index.html` — markup for every panel; loads `presets/presets.js` **then** `sketch.js`
- `sketch.js` — all app logic (~2,500 lines)
- `style.css` — all styling
- `output.html` — the Present/output window
- `presets/` — `*.json` preset files, `presets.js` (generated bundle), `build-presets.py`
- `images/`, `cursors/` — favicon and animated cursor assets
- `CNAME` — `lissa-tool.com` (GitHub Pages custom domain)

Copies under `../presentation/*` and `../code (backup) …` are **old snapshots** — never edit them.

## Critical Implementation Rules

### Language-Specific Rules

- **No modules** — no `import`/`export`. All code is one global script context. Do not introduce ES modules.
- **Scripts share one global scope** — `presets/presets.js` and `sketch.js` are classic scripts, so a top-level name declared in both (e.g. `var X` in one, `const X` in the other) is a fatal SyntaxError that stops **all** of `sketch.js`: blank canvas, and the welcome screen can't be dismissed (its cursor, timer and click handler never attach). Before adding a global, grep for the name. Verify with: `cat presets/presets.js sketch.js > /tmp/combined.js && node --check /tmp/combined.js`.
- **p5.js globals are available everywhere** — `sin`, `cos`, `noise`, `map`, `constrain`, `lerp`, `createVector`, `TWO_PI`, `PI`, `frameRate`, `floor`, `sqrt`, `min`, `max`, `radians`, `pow`, `beginShape`, `vertex`, `endShape`, `stroke`, `noFill`, `push`, `pop`, `translate`, `rotate`, `background`, `clear`, `image`, `rect`, `ellipse`, `line`, `strokeWeight`, `fill`, `noStroke` — all called without any prefix.
- **No `'use strict'`** — `sketch.js` does not use strict mode. Do not add it.
- **Always `Number(this.value)`** — slider `.value` is a string; always wrap with `Number()` before any arithmetic.

### p5.js Framework Rules

- **Global mode only** — never refactor to instance mode (`new p5(function(p){...})`).
- **`draw()` is the loop** — do not add `setInterval` or `requestAnimationFrame`.
- **Canvas parent is `#canvas-container`** — `createCanvas()` calls `canvas.parent("canvas-container")`. Do not move it to `document.body`.
- **`windowResized()` handles resize** — p5 calls this automatically; it sets `meshDirty = true` and nulls `_textMaskCanvas`.
- **Pixel access via offscreen graphics** — to read static image pixel data use `createGraphics()` → draw → `loadPixels()` → slice `.pixels`. Do not read `p5.Image.pixels` without loading.
- **`frameRate()` normalization in LFOs** — LFO phase advances use `(TWO_PI * rate) / frameRate()`. Preserve this in any new LFO-driven animation to keep tempo frame-rate independent.
- **`_fr` is the cached frame rate** — `_fr = frameRate() || 60` is set once at the top of `draw()`. Use `_fr` in new code rather than calling `frameRate()` inline. The `|| 60` guard handles the zero-on-first-frame case.
- **Glow via `drawingContext`** — glow uses `drawingContext.shadowBlur` / `shadowColor`. Always reset `shadowBlur = 0` after drawing to prevent bleed.
- **Transparent background uses composite ops** — when `transparentBg` is true the trail fade uses `globalCompositeOperation = 'destination-out'`. Do not use `background()` with alpha in that branch.
- **Call `_ensureTextCanvas()` before any `_textMaskCtx` access** — the mask canvas is null until first use and is reset to null by `windowResized()`. Always call the guard before writing to `_textMaskCtx`.
- **`textMode.blend` is 0–1** — at `0` the normal draw path runs; at `1` only the text-masked composite renders. Intermediate values crossfade both. Do not treat it as a boolean.

### Video Source Rules

- **`isVideoSource` governs the image pipeline** — when true, `imgPixels` is refreshed each frame in `draw()` via `updateVideoPixels()` (calls `videoCtx.drawImage + getImageData`). Never use `createGraphics()` / `loadImage()` for video.
- **Guard video with `readyState < 2`** — `updateVideoPixels()` no-ops when the video is not ready; `imgPixels` may already exist but hold stale or zero data. Treat the existing `imgPixels` guard (`if (!imgPixels) return`) as still required.
- **`videoCtx` must be created with `{willReadFrequently:true}`** — it already is; preserve this flag when touching video canvas creation code.
- **Video `imgPixels` is a live `Uint8ClampedArray`** — reassigned from `getImageData().data` each frame. Do not cache a reference to it across frames.

### Image Transform Rules

- **All pixel sampling goes through `applyImgTransform(nx, ny)`** — normalised canvas coords `[0,1]` are remapped through `imgScale` / `imgOffsetX` / `imgOffsetY` before hitting `imgPixels`. Never sample raw normalised coords directly inside `_pixelGridCell` or any new sampling function.
- **`imgScale`/`imgOffsetX`/`imgOffsetY` affect lookup, not draw position** — they shift the viewport into the image; they have no effect on where elements are drawn on the canvas.
- **Image mode is not mouse-driven** — `imgFactorX`/`imgFactorY` (sliders + LFOs) replaced the old `mouseX`/`mouseY` modulation. Do not reintroduce mouse input. `imgBlendMode` sets p5 `blendMode()` for the image composite and must be reset to `BLEND` after drawing.

### CSS-Applied Effects (Big Four + Overlay)

- **`brightness` and `contrastLevel` are CSS filters** — applied to `#canvas-container` via `applyCanvasFilter()`. They do not affect p5 drawing values or color calculations; never pass them into `stroke()`/`fill()`.
- **`saturation` is HSL color-space math** — the only "Big Four" value applied inside color computation (`hslToRgb`). The other three (`brightness`, `contrastLevel`, and any future hue) are purely CSS.
- **`colorFilter` is a CSS overlay div** — `#color-filter` uses `mix-blend-mode`; it is not drawn on the p5 canvas. Updated via `applyColorFilter()`. Do not replicate its effect in p5 drawing code.
- **Call `applyCanvasFilter()` and `applyColorFilter()`** whenever `brightness`, `contrastLevel`, or `colorFilter` fields change — just updating the variables is not enough.

### Output Window Rules

- **`mirrorToOutput()` uses `createImageBitmap + postMessage('*')`** — this works across `file://` null origins. Never attempt direct DOM access (`outputWindows[i].document`) on output windows.
- **Photo mode is intentionally NOT mirrored** — `draw()` returns early inside `showImage` mode before `mirrorToOutput` is called. Do not add mirroring inside `drawPhotoMode()`.
- **Max 3 output windows** — `outputWindows` is an array filtered for `!w.closed` each frame. Multi-window sends clone bitmaps via a second `createImageBitmap` pass before transferring any.
- **Meta state via `BroadcastChannel('lissa-output')`** — CSS filter string and `colorFilter` object are sent as `{type:'meta'}` messages, separate from pixel-frame messages. The channel also receives heartbeats from output windows.

### Presets & Startup Rules

- **Presets are saved-settings JSON files** in `presets/` — made with the app's Save button, then dropped in the folder. The filename is the display name (`-`/`_` → spaces, alphabetical order).
- **The app reads `presets/presets.js`, not the JSON files** (no `fetch()` on `file://`/static hosting). It defines `var LISSA_PRESETS = [{ name, state }]`. After adding/removing/renaming a JSON file, run `python3 presets/build-presets.py` — never hand-edit `presets.js`.
- **Load presets with `loadLissaPreset(preset)`** — it layers the preset over `_defaultState` (captured in `setup()` before anything else changes state), because older saves lack newer fields (vignette, textMode, audioIn, newer LFO keys). Calling `restoreState(preset.state)` directly would leak the previous look's values into those fields. It does not push history; callers do.
- **Two unrelated preset systems exist** — the old built-in `const PRESETS` (classic/spiro/rose) and `applyPreset(name)` near the top of `sketch.js` are unused leftovers. Do not reuse those names; the live system is `LISSA_PRESETS` / `hasLissaPresets()` / `loadLissaPreset()` / `markActivePreset()`.
- **Presets panel** — the first bottom-bar pill (`presetsBody` section, `#presetList`). Chips are built in `setup()` from `LISSA_PRESETS`; clicking one loads it and pushes one history entry. The bold chip is the last-loaded preset.
- **`presetName` lives only in undo history** — `pushHistory()` tags each snapshot with `_activePresetName` so undo/redo can re-bold the right chip. It is not part of `captureState()`, so it never ends up in saved settings files.
- **Startup** — the welcome screen is an opaque cover; at the end of `setup()` one random preset is loaded (falls back to `randomizeColors()` + `randomizeParams()` if `presets.js` is missing) and that state becomes the first history entry. The welcome screen dismisses on click or after 20s and shows an animated GIF cursor that follows the mouse.

### Testing Rules

- **No test framework exists** — do not generate test files or add testing dependencies unless explicitly asked.
- **Manual verification is the workflow** — open `index.html` in a browser and exercise the UI.
- **Always syntax-check scripts together** after JS edits (see "Scripts share one global scope"): a per-file `node --check` will not catch cross-script name clashes.
- **If tests are added** — this is a browser-only app; any future framework must run in-browser (e.g. QUnit) or mock p5 globals + DOM (e.g. Jest + jsdom).

### Code Quality & Style Rules

- **No linter/formatter** — no `.eslintrc`, `.prettierrc`, or editor config. Do not add them.
- **Section banners** — `sketch.js` uses `// ===...===` banners with labels to divide sections (STATE, HELPERS, SETUP, DRAW). New logical groups should follow this pattern.
- **camelCase everywhere** — variables, functions, and HTML element IDs. ID convention: `{paramKey}Slider` for range input, `{paramKey}Value` for display `<span>`.
- **Flat file structure** — all logic in `sketch.js` (`presets/presets.js` is data only). Do not split into modules without explicit instruction.
- **Decimal precision matches UI** — use `.toFixed(decimals)` with the same count as the slider binding: `2` for most params, `3` for `speed`/`stepSize`, `0` for `trail`/`pointCount`.
- **Comments only where non-obvious** — existing comments explain math or mode intent. Do not add obvious or redundant comments.

### Development Workflow Rules

- **No version control** — no git. Do not suggest git commands, branching, or PRs. Backups are dated folder copies (e.g. `../code backup 09.10.26/`); suggest one before large changes.
- **Run by opening `index.html` directly** — no local server needed. All assets are CDN-loaded.
- **Deployment: GitHub Pages (static only)** — no server-side code, no Node backend, no API routes, no runtime env vars. Everything must work as a fully static site.
- **No `fetch()` or network requests** — `file://` protocol and static hosting block XHR/fetch to localhost or relative non-asset paths.
- **Settings persistence = JSON export** — `saveSettings()` / `loadSettings()` produce timestamped JSON files. No backend, no database.
- **SVG export is geometry-only** — reconstructs from params at save time; does not capture animated state.
- **Bachelor Project** — code clarity and documented design decisions matter alongside functionality.
- **Spec status is stale** — the utility panel, vignette, image-mode and sound-input specs in `_bmad-output/implementation-artifacts/` still say `draft`, but all four are implemented in the code. Check the code, not the spec status, before building anything they describe. `deferred-work.md` is partly done (the LFO `log10(0)` guard is in; the double history entry on Random is not).

### Critical Don't-Miss Rules

**Anti-patterns:**
- **Never `background()` with full opacity in line mode** — the trail depends on a semi-transparent background each frame (`trail` param = alpha).
- **Never skip `meshDirty = true`** after changing any mesh parameter — stale geometry will silently persist.
- **Never add state without updating both `captureState()` and `restoreState()`** — new state will be lost on undo and settings load/save. Current state shape includes: `params`, `bgColor`, `lineColor`, `drawMode`, `curveShape`, `showCurve`, `meshAnimating`, `meshAnimSpeed`, `imgDrawMode`, `imgCols`, `imageStrength`, `lfos`, `colorFilter`, `vignette`, `glowEnabled/Size/Intensity`, `imgScale/OffsetX/OffsetY`, `imgFactorX/Y`, `imgBlendMode`, `saturation`, `brightness`, `contrastLevel`, `showImage`, `transparentBg`, `audioIn`, `textMode`. New fields need a fallback default in `restoreState()` (older saves and presets lack them).
- **Never increase `pointCount` cap beyond 2000 without reason** — mesh is O(n²); the cap is intentional.

**Edge cases:**
- **Guard `imgPixels`** — always check `if (!imgPixels) return <fallback>` before sampling; it is null until an image or video is uploaded.
- **`frameRate()` returns 0 on first frame** — use `_fr` (already guarded with `|| 60`) rather than calling `frameRate()` directly in new code.
- **Canvas resize invalidates mask canvas** — `windowResized()` sets `_textMaskCanvas = null`. Any new globally-cached canvas must also be reset there.
- **Video pixels lag one frame behind** — `updateVideoPixels()` runs at the start of `draw()`; pixel data reflects the previous decoded frame, not the current one.
